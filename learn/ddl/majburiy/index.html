#DEFAULT

DEFAULT ustun INSERT da yozilmaganda qo'yiladigan qiymat:

Hisobot 'yangi' va 3 ni oldi. Serverning muhimligi esa NULL: unga NULL ataylab yozilgan.

DEFAULT va NULL

DEFAULT faqat ustun umuman yozilmaganda ishlaydi. NULL ataylab yozilsa, u ham qiymat hisoblanadi va DEFAULT jim turadi. Ustun hech qachon NULL bo'lmasligi kerak bo'lsa, DEFAULT ga qo'shimcha NOT NULL yozing. status da aynan shunday: unga NULL yozilsa, qator rad etiladi.

Yordam xizmati murojaatlari uchun tickets jadvalini yarating: id (butun son, birlamchi kalit), title (matn, majburiy), status (ko'rsatilmasa 'ochiq'), priority (ko'rsatilmasa 2). Ikki murojaat qo'shing: 1-raqamli "Printer ishlamayapti" faqat id va title bilan, 2-raqamli "Parolni tiklash" esa 1-muhimlik bilan. Oxirida SELECT id, title, status, priority FROM tickets ORDER BY id yozing.

#Birlamchi kalit

Birlamchi kalit (PRIMARY KEY) qatorni boshqalaridan ajratib turadi. U takrorlanmaydi va NULL bo'lmaydi. orders dagi ikkita 5-buyurtma kalitsiz jadvalda paydo bo'ladi:

Uchinchi qator kalitni takrorladi va butun INSERT bekor bo'ldi: Choy ham, Piyola ham qo'shilmadi. Bitta buyruq bo'lib bajarilmaydi.

Jadvalda birlamchi kalit bitta. U bir nechta ustundan ham tuzilishi mumkin, buni keyingi qadamda ko'rasiz.

Dialektlar farqi

PostgreSQL'da birlamchi kalit o'zi NOT NULL. SQLite'da tarixiy sabab bilan bunday emas: INTEGER PRIMARY KEY dan boshqa birlamchi kalit NULL ni o'tkazadi.

Ikkala bazada bir xil ishlashi uchun code TEXT NOT NULL PRIMARY KEY deb yozing.

#Avtomatik raqam

Ko'pincha raqamni baza o'zi berishi kerak: yangi mijoz id siz qo'shiladi. Buning yo'li ikki bazada har xil. SQLite'da aynan INTEGER PRIMARY KEY deb yozilgan ustun shuni qiladi, PostgreSQL'da esa yo'q:

PostgreSQL'da avtomatik raqam SERIAL yoki GENERATED ... AS IDENTITY bilan yoziladi:

CREATE TABLE members (
  id SERIAL PRIMARY KEY,
  name TEXT NOT NULL
);

-- yoki standart SQL ko'rinishi
CREATE TABLE members (
  id INTEGER GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  name TEXT NOT NULL
);

SQLite bu so'zlarni bilmaydi. SERIAL ni u oddiy tur nomi deb oladi, va ustun rowid ga aylanmaydi:

Dialektlar farqi

SQLite'da har jadvalda yashirin rowid bor, INTEGER PRIMARY KEY uning ikkinchi nomi. INT PRIMARY KEY yoki SERIAL PRIMARY KEY esa oddiy ustun, va unda id siz qatorlar NULL bilan saqlanadi. O'chirilgan raqamlar ham har xil: PostgreSQL ketma-ketligi orqaga qaytmaydi, SQLite esa eng katta id ga bir qo'shadi va oxirgi qator o'chirilsa, uning raqamini qayta beradi (AUTOINCREMENT buni to'xtatadi).
