#Avval SELECT

O'zgartirish buyrug'ini yozishdan oldin xuddi shu WHERE bilan SELECT yozing va nima o'zgarishini ko'ring:

Bitta buyurtma, 3-raqamli. Endi SELECT * ni DELETE ga almashtirish qoldi, shart esa sinalgan:

Tajribali dasturchilar ham shunday qiladi. Ayniqsa NULL li ustunlar va NOT IN bor joyda: SELECT nechta qator qaytarsa, DELETE ham aynan shularni o'chiradi.

RETURNING o'zgargan qatorlarni buyruqning o'zidan qaytaradi. PostgreSQL'da ham, SQLite'da ham (3.35 versiyadan) bor:

DELETE FROM orders
WHERE status = 'bekor'
RETURNING id, amount

U ayniqsa INSERT da qulay: INSERT INTO customers (name) VALUES ('Nodira') RETURNING id baza bergan raqamni darhol aytadi, keyin uni qidirib yurish kerak emas.

#Hammasi yoki hech narsa

products.stock da CHECK (stock >= 0) sharti bor. Hamma mahsulot qoldig'idan 5 tani ayiramiz:

Choy 40 dan 35 ga tushishi mumkin edi, lekin Piyolada 0 bor va u manfiy bo'lib qoladi. Baza bitta buyruqni bo'lib bajarmaydi: bitta qator shartni buzsa, hech bir qator o'zgarmaydi.

Bir nechta buyruq birga bajarilishi kerak bo'lsa, ular tranzaksiyaga o'raladi. Pul o'tkazmasi ikki UPDATE: biridan ayirish, ikkinchisiga qo'shish. Birinchisi bajarilib, ikkinchisi yiqilsa, pul yo'qoladi:

BEGIN;
UPDATE accounts SET balance = balance - 200000 WHERE id = 1;
UPDATE accounts SET balance = balance + 200000 WHERE id = 2;
COMMIT;

COMMIT gacha o'zgarishlarni boshqa foydalanuvchilar ko'rmaydi. Oradagi xatodan keyin ROLLBACK yozilsa, ikkala buyruq ham bekor bo'ladi.

#O'zgarayotgan jadvaldan o'qish

UPDATE dagi subquery yangilanayotgan jadvalning o'zini o'qishi mumkin. Shunda bazalar har xil yo'l tutadi. Farqni ko'rsatish uchun har mahsulot narxi o'rniga uning arzonlik bo'yicha o'rnini yozamiz:

Dialektlar farqi

PostgreSQL'da subquery buyruq boshlangandagi jadvalni ko'radi va o'rinlar to'g'ri: Choy 1, Sharbat 2, Piyola 3. SQLite qatorlarni birma-bir yangilaydi va subquery oldingi qatorlarning yangi qiymatlarini ko'radi. Sharbat navbati kelganda Choy, Piyola va Choynakning narxi allaqachon 1, 3 va 7, Sharbat 4-o'ringa tushib qoladi.

WHERE dagi subquery'da bu muammo yo'q: ikkala baza ham avval o'zgaradigan qatorlarni topib oladi. SET da o'sha jadvaldan o'qish kerak bo'lsa, qiymatlarni hosila jadvalda oldindan hisoblang. UPDATE ... FROM hosila jadvalni o'zgartirishlar boshlanishidan oldin tayyorlaydi:

#Qisqacha

Nima kerak Qanday yoziladi
Qator qo'shish INSERT INTO t (a, b) VALUES (1, 2), (3, 4)
Avtomatik id id ni ustunlar ro'yxatiga yozmang; raqamni RETURNING id qaytaradi
So'rov natijasini qo'shish INSERT INTO t (a, b) SELECT ... (ustunlar o'rni bo'yicha)
O'zgartirish UPDATE t SET a = a + 1, b = 'x' WHERE ...
SET dagi qiymatlar o'zgarishdan oldingi qatordan; almashtirish: SET a = b, b = a
Foiz ROUND(price * 1.1); butun sonlarda avval ko'paytiring: price * 110 / 100
Boshqa jadvaldan SET a = (SELECT ...) WHERE id IN (...) yoki UPDATE t SET ... FROM s WHERE s.id = t.id
O'chirish DELETE FROM t WHERE ...
Boshqa jadvalda yo'qlarini WHERE NOT EXISTS (...); NOT IN va NULL dan ehtiyot bo'ling
Takrorlar WHERE EXISTS (... AND c.id < t.id)
Murakkab shart WITH x AS (...) DELETE FROM t WHERE id IN (SELECT id FROM x)
Bor bo'lsa o'tkazib yuborish INSERT ... ON CONFLICT (kalit) DO NOTHING
Bor bo'lsa yangilash ON CONFLICT (kalit) DO UPDATE SET a = t.a + excluded.a
Sana PostgreSQL: d + 7; SQLite: date(d, '+7 days')
